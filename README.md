# Бессмертная память

Каталог необычных и исторических памятников России с фотографиями, лайками и картой страны. Каждая запись — с проверенной историей и ссылкой на источник.

## Технологии

- Vue 3 (Composition API) + Vite 6
- Tailwind CSS 4, vue-router, Leaflet (карта)
- Бэкенд: Node.js (только `node:http`, без зависимостей)
- Данные каталога клиент получает через `/api/catalog`; в бандле остаётся только офлайн-копия (ленивый чанк для service worker)

## Возможности

- Каталог памятников: поиск по названию/городу/региону, фильтры по категории (со счётчиками) и региону, сортировки, режим «только с фото», кнопка сброса фильтров
- Народный рейтинг (Топ-10 / Топ-50 / Топ-100): базовые лайки каталога + личные лайки посетителя, миниатюры и медали за топ-3
- Страница памятника: галерея с атрибуцией фото, лайтбокс, факты, карта (виджет Яндекс Карт), кнопка 👍, «Поделиться»
- «Добавить фото» — посетитель присылает фото по ссылке, публикация после модерации
- Админ-панель `/admin`: вход по паролю (сессионные токены, timing-safe сравнение), модерация фото, стены памяти и заявок на памятники
- Карта страны `/map`: все памятники, золотые метки — с фото, серые — ждут фото, попап с миниатюрой и SPA-переходом
- Охваченность по регионам `/regions`: статистика фото с сортировкой
- Краудсорсинг: «Предложить памятник» с автопроверкой дублей (название/точка в 250 м) и геолокацией «Я на месте»; одобрение мгновенно добавляет запись в каталог — без пересборки
- «Стена памяти» на каждой странице памятника: короткие истории посетителей с модерацией
- PWA: офлайн-режим (SW: cache-first для ассетов, network-first для страниц/каталога/стены, кэш картинок Wikimedia с лимитом), версия SW штампуется при сборке
- SEO: sitemap.xml и robots.txt генерируются при сборке из данных каталога (`SITE_URL=... npm run build`)
- Памятники без фотографии — аккуратный плейсхолдер, случайных стоковых картинок нет

## Данные

- `src/data/monuments.js` — каталог: название, город, регион, год, категория, история, координаты, фото с источниками, `factsSource` — ссылка на источник фактов
- Фотографии — Wikimedia Commons + локальные в `public/photos/`; источник всегда выводится рядом с изображением
- История сбора данных:
  - исходные 200 записей проверены по источникам (Википедия, региональные СМИ); неподтвердившиеся удалены — `scripts/enrich/` (батчи + `merge.mjs`, отчёт `merge-report.json`)
  - города >10k населения: `scripts/build-settlements.mjs` → `harvest-monuments.mjs` (по одному примечательному памятнику на город, чекпоинт, пауза 8с)
  - фото — четыре прохода по открытым источникам (`find-photos*.mjs` с чекпоинтами, отбраковка в `curate-found.mjs`, слив в `merge-found-photos.mjs`)
- Хранилище заявок: `server/data/*.json`

## Запуск

```bash
npm install
npm run dev      # разработка (http://localhost:5173; API-прокси на 8765)
npm run build    # сборка в dist/
npm start        # продакшен: весь сайт + API на http://localhost:8765
```

Полный цикл разработки: `npm start` и `npm run dev` в двух терминалах (без сервера каталог возьмётся из офлайн-копии бандла, но заявки/стена работать не будут).

При первом запуске сервер создаёт `server/config.json` с паролем администратора (выводится в консоль один раз, дальше хранится только sha256-хэш). Админ-панель: `http://localhost:8765/admin`.

## Структура

```
src/
  stores/catalog.js           # каталог: /api/catalog + офлайн-фолбэк-чанк
  data/monuments.js           # данные каталога (источник истины)
  views/                      # HomeView, MonumentDetail, CountryMap, RegionCoverage
  components/                 # карточки, галерея, модалки, фильтры, рейтинг, стена
  composables/                # useVoting, useModalScrollLock
server/
  server.mjs                  # HTTP-сервер: статика, API, модерация, security-заголовки
  admin/admin.html            # админ-панель
scripts/
  enrich/                     # верификация/обогащение историй + слив результатов
  harvest-monuments.mjs       # харвест по городам (Википедия, чекпоинт)
  find-photos*.mjs            # поиск фото на Commons/Openverse
  merge-*, curate-*, audit-*  # слияние и контроль качества находок
  deploy/deploy.sh            # деплой на VDS (изолированный systemd-юнит)
sw.template.js                # service worker (версия штампуется при сборке)
```

## Деплой

`scripts/deploy/deploy.sh` — установка на VDS: собственный Node в `/opt/memorial-site/node`, systemd-юнит с хардненингом, приложение на `127.0.0.1:8766`. Наружная публикация — nginx server-block на ваш домен (HTTPS). Сборка сайта выполняется при деплое; одобрение заявок в рантайме пересборку не требует.
